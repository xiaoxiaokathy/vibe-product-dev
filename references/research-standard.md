# Research standard

Research exists to reduce a decision, not to decorate a plan. Begin with a question in this form:

`Decision: <what must be selected or believed>; question: <what evidence would change it>; deadline: <when it matters>.`

## Source order

Prefer primary sources: official documentation, source code and release notes, original papers, standards bodies, public regulatory text, direct customer evidence, and independently reproducible measurements. Use secondary analysis only to discover candidates or explain context; label it as such.

For each source write:

- `RES-#` and a stable URL/citation;
- date accessed and publication/version date if known;
- concise factual finding, separated from interpretation;
- applicability to this project and important limitations;
- the decision influenced and confidence level.

## Comparative recommendations

Compare options against criteria derived from the brief, not a generic popularity ranking. Include a do-nothing/simpler option. State uncertainty; do not manufacture a precise score where evidence is qualitative.

## Unsafe conclusions

Do not use stale web snippets for legal, pricing, security, compatibility, model, API, or product-availability claims. Re-check authoritative sources immediately before relying on such claims. Do not represent a search result as a test performed in the target repository.
